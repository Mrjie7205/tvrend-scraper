# tvrend-scraper

欧洲电视零售渠道的**价格 / 目录抓取器**,跑在 GitHub Actions 上(公开仓库,Actions 分钟无限)。
抓取结果同步到另一个私有仓库做分析。本仓库只负责"抓取",不含任何业务字典或分析逻辑。

## 做什么

| 任务 | 频率 | 产出 |
|---|---|---|
| 价格监控 `monitor_prices` | 每天 | `raw/prices.csv`(跟踪 SKU 的当日价格) |
| 目录反向拉 `catalog_scrape` | 每周 | `catalog/*.csv`(在售商品列表快照) |

渠道:Boulanger(FR)、Currys(GB)、Elkjop(NO)。Amazon(DE/GB/IT/ES) 走独立 daily catalog 链路。每个渠道一个 adapter,新增渠道只需加一个 adapter。

## 目录

```
scripts/
  monitor_prices/    每日价格抓取(渠道批量快照优先 + 商品详情页兜底)
  catalog_scrape/    每周目录抓取
mapping/
  channel_links.csv  输入:盯哪些 SKU / 对应链接(由上游私库每周刷新后推入)
raw/                 抓到的价格(滚动窗口;完整历史在私库)
catalog/             目录快照
```

## 本地运行

```bash
pip install -r requirements.txt
python -m playwright install chromium
cd scripts
python -m monitor_prices.run_daily      # 抓价格
python -m catalog_scrape.run_weekly      # 抓目录
```

环境变量:`HEADLESS_MODE`(默认 true)、`MONITOR_CONCURRENCY`(默认 3)、
`MONITOR_SKU_TIMEOUT_SECONDS`(单商品总时限，默认 120 秒)、
`PLAYWRIGHT_CLOSE_TIMEOUT_SECONDS`(浏览器资源关闭时限，默认 10 秒)。

## 每日抓价策略

不同渠道使用适合本站结构的获取方式，而不是强行共用一种爬法：

| 渠道 | 主路径 | 回退路径 |
|---|---|---|
| Boulanger | 五大品牌电视 facet 批量价格快照 | 未命中 SKU 打开商品详情页 |
| Currys | 电视总类目分页快照；每页使用全新浏览器会话 | 未命中 SKU 打开商品详情页 |
| Elkjop | 站点商品动态接口 | 商品详情页 |
| Amazon | 独立的多国家 catalog 搜索链路 | 搜索补漏与详情页尺寸变体 |

Boulanger/Currys 的批量快照有两道完整性保护：商品数与跟踪清单覆盖率不足时整批作废；
价格相对历史数据发生系统性错位时整批作废。作废后自动回到原有详情页抓取，避免为了速度写入错误价格。

关联不依赖标题猜测：Currys 使用 URL 末尾商品 ID，Boulanger 使用 `/ref/<id>`，因此标题改名不会串价。

每日定时任务中，Boulanger、Currys、Elkjop 分开抓取；一个渠道异常不会阻塞另一个渠道。
抓取过程中每完成一条就更新 `scripts/monitor_artifacts/partial_prices.csv`，Action 无论成功或失败
都会上传该检查点和失败现场，便于中断后的审计与恢复。

抓取成功后只交接本轮成功价格及运行清单。三个独立发布任务使用共享排队组，进入发布阶段后
从 `main` 最新版本合并全部 11 列唯一记录，再统一保留现有 45 天窗口。普通推送遇到其他提交
抢先到达时重新读取、重新合并，不使用冲突自动取一方或强制推送。相同型号和时间的不同报价
仍分别保留；重复处理同一产物不增加记录。历史价格依据抓取日期和时间选择，不依据文件追加顺序。

手动 `max_skus` 非零或手动运行非 `main` 分支时只生成诊断和价格产物，不发布正式价格。
零条有效价格、产物身份/哈希不符或推送后记录缺失均明确失败，不将缺失数据标记为已发布。

## 全渠道失败现场

日抓及目录抓取在实际失败页面关闭前调用共同的现场采集器。Amazon 入口异常及返回失败均覆盖，
Currys 在每个真实分页窗口关闭前采集，Elkjop 接口没有页面时仍保留最小摘要。

- 现场位于 `scripts/failure_artifacts/`，仅作为 Actions 附件保存，不提交 Git 或导入正式价格。
- JSON 包含运行编号、国家/渠道、失败阶段、HTTP 状态、脱敏 URL 和错误类别；浏览器可用时保存可见结构及截图。
- 截图遮挡输入框、账户和配送地址；不保存 Cookie、请求头、浏览器存储、隐藏字段、完整 HTML 或 HAR。
- 采集总时限为 4 秒；每个渠道/国家/错误类别默认最多 2 张、每个进程最多 48 张截图。超过上限记录省略数量。
- 常规事件摘要上限为 300 份；新错误类别仍保留首条（最多 64 类），其余按渠道和错误类别计入 `summary.json`，避免重复异常挤满附件。
- 无法截图或浏览器已断开时保存原因；诊断失败不改写原始抓取失败，也不拖住资源清理。
- 日抓附件以 `monitor-<channel>-<run>-<attempt>` 命名，目录失败附件以 `failure-*` 命名；均保留 14 天。

价格产物绑定运行尝试号。发布脚本会自动处理推送竞争；若产物或发布 job 已失败且需要在 Actions
手动重跑，应选择整个工作流，使抓取与发布使用同一新尝试号，不能借用上一次尝试的产物冒充本轮结果。

`Verify scraper diagnostics and safe publication` 工作流只做验收，不写目录和价格：运行自动测试，
在真实浏览器中验证明确标注的合成失败页面，检查三个共享排队任务都保留，并可对 GB/IT 执行
最小入口诊断。入口诊断附件生成成功不代表完整目录采集恢复，正式抓取仍按原有校验决定成功或失败。

## 大幅价格波动快照

当可比历史价格为正值时，新价达到旧价的 **2 倍及以上**，或降到旧价的 **一半及以下**，
自动保存价格事件 JSON 和脱敏网页截图。边界包含 +100% 与 -50%；没有历史价、零基线、
币种不同或非有限数值不进行涨跌比较。新价为零可作为异常候选留证，但仍不能作为有效报价发布。

- Boulanger、Currys、Elkjop 按现有型号／国家／渠道／币种冻结本轮开始前的最近成功观测；原始11列没有历史URL，因此明确标注这个比较精度，不冒充同一listing的历史。
- Amazon 按同一国家、ASIN、币种，从开始前最新合格目录冻结原币价格基线；不使用被拒绝的诊断候选做基线。
- 每个唯一触发事件保存旧价、新价、变化比例、两次观测时间、商品与来源、抓取运行编号、页面取证来源和验收状态。
- 已有商品页直接截图；类目／API报价另行取得商品页时，单独记录复核价格与结果，不能将复核页冒充原报价来源。
- 类目异常价被完整性或历史价格门禁拦下时，先保存未验收候选，再复用既有商品页请求附加复核结果；复核失败或价格不同也保留候选，不把它写入正式价格。
- 默认对每个唯一触发事件尝试截图；页面不可用、访问受阻、超时或显式运维上限都会在 JSON 中注明。留证失败不改写已验证的价格，也不会把合法促销自动删除。
- 数据在 `scripts/price_artifacts/`，Actions 的 `price-changes-*` 附件独立保留 **90天**；普通失败现场仍保留14天。超过保存期不会承诺图片仍可下载，需在到期前导出所需附件。
- 价格变动事件的 `accepted` 表示采集校验通过；正式发布是否成功还应检查同一次 Actions 的发布任务。合成验收附件会明确标记，不会写入价格历史。

`python scripts/price_anomalies.py summary --output-dir scripts/price_artifacts` 可生成摘要；
`--github-summary <文件>` 可附加中文表格。已有质量门槛仍有效，未通过的目录候选标记为 rejected。

## 本轮运行优化

诊断与正式入口共用浏览器工厂。`SCRAPER_BROWSER_PROFILE=current` 为生产默认，保留此前已运行
的浏览器启动与会话配置；`native` 为显式兼容性试验，使用 Playwright 配套 Chromium 的原生身份
和真实市场语言／时区。新配置尚未通过所有渠道的实站验收，因此不默认替换生产配置。
运行开始时确定配置，遇已确认的访问校验只保留现场并停止相应请求，不自动切换身份继续尝试；
普通传输暂错仅作有限恢复。

Currys 先区分访问拒绝／限流，再判断明确404或410，最后核对商品身份；200跳到类目页记为
重定向待核验，不自动判定整个型号下架。目录逐页保存账本，暂错可有限补页；周目录缺页或未
观察到末页时拒绝完整发布，日价格仍沿用原有数量、覆盖率与历史价格门槛。

## Amazon 本轮目录验收

- 四国分别采集，某国失败时仍保存其他国家成功产物，但整轮必须标记失败。
- 每国 artifact 包含本次运行 ID、尝试号、代码 SHA、时间窗和目录哈希；汇总阶段只接收本轮经过验证的产物。仓库里已有的同日文件不计作本轮成功，也不补充缺失国家。
- 配送栏临时缺失时短等一次；仍无法确认本地邮编时最多恢复一次地址，再回到原商品或搜索页面复核。仅恢复分支新增严格页面身份检查，正常页沿用既有行为。
- 恢复后重新提取当前页面；邮编、页面身份仍不匹配，或恢复后仍停留在访问校验／继续购物中间页时，拒绝本轮结果。历史目录仅供发现待查商品，不把缓存价格写成新观测。
- 四国已核实的纯“继续购物”中间页，在HTTP200、同市场、唯一明确继续操作且没有验证码或人工验证控件时，最多执行一次页面提供的正常导航。同一按钮的无障碍包装可按已核实的表单与动作去重；目标仍须是同市场正常商店页，并继续通过配送、币种及价格校验。重复中间页和真实验证码仍拒绝。
- 旧配送接口缺少参数时，复用已确认正常的当前页面打开配送弹窗，避免不必要的首页重载。代码测试产生的模拟故障独立保存，不能混入正式抓取的现场附件。
- 若同一天已有成功目录而后续采集失败，旧目录可继续保留使用，但失败的后续运行必须如实报告。目录日期与执行次数是两个不同的验收维度。

本地可使用 `python -m catalog_scrape.run_weekly --only amazon_it` 单独验证意大利；Elkjop 使用 `--only Elkjop`。完整目录应通过原有行数、分页、品牌及价格检查，不能用缩小采集范围的调试结果冒充全量快照。

## 说明

- 抓取读取公开分类页、公开商品接口或公开商品页，**不需要任何账号 / 密钥 / 凭据**。
- `mapping/channel_links.csv` 由上游维护后推入;本仓库不生成它。
